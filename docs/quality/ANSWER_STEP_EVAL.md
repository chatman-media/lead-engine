# Вклад опциональных LLM-шагов answerWithRag (#515)

Замер того, что реально дают опциональные LLM-шаги пайплайна ответа — query
rewrite, multi-query, reflection — против их стоимости (доп. LLM-вызовы и
латентность). Методология «сильным моделям нужно меньше лесов»: шаги
добавлялись под слабые модели; если шаг не двигает метрики даже на локальной
8B-модели, на продовой (gemini-flash и сильнее) он тем более балласт.

## Как мерили

- Раннер: `apps/api/scripts/run-answer-step-eval.ts` поверх
  `evaluateRagGoldenCases` (kb), матрица из 6 вариантов: baseline (все шаги
  включены), −rewrite, −multi-query, −reflection, prod default (только
  rewrite — текущее поведение не-exchange вертикалей), minimal (всё выключено).
- Датасет: `packages/kb/evals/answer-steps.jsonl` — 17 RU-кейсов, 4 группы:
  контрольные (d\*), эллиптичные follow-up с history (a\* — целевая зона
  rewrite), лексический разрыв вопрос↔документ (b\* — целевая зона
  multi-query), ловушки на галлюцинации (c\* — целевая зона reflection).
- Клиенты реальные: chat ollama/qwen3:8b (think off), embed ollama/bge-m3,
  InMemoryKbStore с настоящим cosine+BM25 hybrid. 2 повтора на вариант.
- Два режима корпуса: изолированные мини-сторы (3–4 дока на кейс) и общий
  стор на 57 доков с перекрёстными дистракторами (ближе к продовому KB).

## Выводы по шагам

**Query rewrite** — вклад не подтверждается. Дельты разнонаправленные в
пределах шума (±2 кейса): в связке с другими шагами +5.9 п.п. pass, в
сравнении prod default vs minimal — −5.9 п.п.; recall без rewrite на общем
сторе тот же (94.1%). Hybrid retrieval (vector+BM25) справляется с
эллиптичными follow-up'ами и без переписывания запроса. Цена: +1 LLM-вызов и
+0.8–2 c на каждом ходе с историей. **Решение: дефолт в RagReplyStrategy
переключён на off**, флаг `rewriteQueryBeforeRetrieval: true` остаётся
доступным per-tenant/per-call.

**Multi-query** — в проде и так выключен; замер подтверждает: на общем сторе
выключение multi-query даже улучшило recall (94.1% против 91.2%), стоимость
+1 вызов и ~2x латентности. **Решение: остаётся opt-in, код не трогаем.**

**Reflection** — pass/grounded идентичны с ним и без него в обоих режимах;
из 2 forbidden-нарушений не срезал ни одного (они одинаковы во всех
вариантах). Цена +1 вызов и ~2 c. **Решение: для не-exchange остаётся
выключенным (как и было). Exchange-дефолт (reflect=on) не трогаем** — там
reflection встроен в safety-стек (`EXCHANGE_SAFE_FALLBACK`-путь), а
exchange-специфику этот датасет не покрывает.

## Оговорки и перепроверка на проде

- Локальная 8B-модель — нижняя граница: если шаг бесполезен для неё, для
  прод-модели он бесполезен тем более; обратное неверно, поэтому решения
  приняты только по шагам с отсутствием вклада, а не по «улучшениям».
- Перепроверка на проде (gemini-flash + openai embeddings + BYOK тенанта):

  ```bash
  DATABASE_URL=... PLATFORM_MASTER_KEY=<правильный ключ> \
    bun run apps/api/scripts/run-answer-step-eval.ts --tenant 3 --shared-kb --repeats 2
  ```

  Внимание: секреты в локальной БД зашифрованы не тем ключом, что в `.env`
  (auth tag mismatch) — нужен ключ, которым реально шифровали.
- Датасет — 17 кейсов: ловит крупные эффекты (>±6 п.п.), мелкие — нет.
  Расширяется добавлением строк в JSONL без правки кода.
