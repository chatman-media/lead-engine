# Инструкция по поддержке

Как оператор сопровождает кандидата вместе с ботом: режимы диалога,
ручной перехват, эскалация и сбои. Про саму воронку (статусы лида,
intake/visa-анкеты, кнопки одобрить/отклонить) — отдельный документ
[LEADS.md](LEADS.md). Про содержание системы (оплата OpenRouter, смена
ключей, перезапуск, восстановление базы) — [RUNBOOK.md](RUNBOOK.md).

## Роль оператора

Бот ведёт диалог сам: отвечает из базы знаний (RAG), держит персону,
собирает анкету, эскалирует решение в чат лидов. Оператор подключается
там, где нужен человек:

- принять решение по лиду (одобрить / отклонить) — см. [LEADS.md](LEADS.md);
- ответить на вопрос, по которому бот промолчал;
- перехватить диалог вручную, если кандидат просит человека или разговор
  пошёл не так;
- пополнить базу знаний, чтобы бот в следующий раз ответил сам.

Главный экран — `/admin` (список диалогов, обновляется в реальном времени
через WebSocket).

## Режимы диалога

У каждого диалога (`conversations.mode`) три состояния:

| Режим | Что значит | Кто отвечает |
|-------|------------|--------------|
| `ai` | Обычный режим | Бот отвечает автоматически на каждое сообщение |
| `queued` | Эскалировано — ждёт оператора | Бот молчит, диалог поднят в очереди |
| `human` | Оператор перехватил диалог | Отвечает только оператор, бот не вмешивается |

Переходы:

- `ai → queued` — автоматически при эскалации (см. ниже).
- `ai/queued → human` — оператор нажимает **Take over** на странице диалога.
- `human → ai` — оператор нажимает **Release**, диалог возвращается боту.

## Ручной перехват и ответ

На странице диалога (`/admin/chats/:id`):

1. **Take over** — берёте диалог на себя (`mode=human`), бот замолкает.
2. Пишете ответ прямо из браузера — он уходит кандидату в Telegram и
   сохраняется в истории.
3. **MEMORY pane** — можно отредактировать факты, которые бот запомнил о
   кандидате (имя, город и т.п.), чтобы дальше он отвечал точнее.
4. **Release** — возвращаете диалог боту (`mode=ai`), когда вопрос закрыт.

Пока диалог в `human`, бот не отвечает — не забывайте про Release, иначе
кандидат останется без авто-ответов.

## Эскалация

Бот сам поднимает диалог оператору в двух случаях:

1. **Кандидат просит человека.** Сообщение содержит «оператор»,
   «менеджер», «человек», `operator`, `human` (и однокоренные) →
   диалог уходит в `queued`.
2. **Бот не знает ответа.** RAG вернул `NO_CONTEXT` (в базе знаний нет
   опоры для ответа) — бот не выдумывает, а молчит, и вопрос попадает в
   очередь незнакомых вопросов.

> В режиме ожидания визы (`docs_pending` / `submitted`) бот работает
> мягче — `NO_CONTEXT` не эскалирует, бот отвечает спокойной отпиской и
> остаётся в `ai`. Подробнее — [LEADS.md → support mode](LEADS.md).

## Очередь незнакомых вопросов

Каждый `NO_CONTEXT`-вопрос попадает в очередь `/admin/kb-suggestions`.
Оператор:

- видит вопрос кандидата и контекст диалога;
- пишет ответ → он пополняет базу знаний, и дальше бот отвечает на такой
  вопрос сам.

Если задан `ADMIN_TG_USER_ID`, оператор получает Telegram-DM на каждый
новый вопрос в очереди — не нужно держать админку открытой.

```bash
ADMIN_TG_USER_ID=123456789   # Telegram user id оператора (не username)
```

Свой id — через [@userinfobot](https://t.me/userinfobot).

## Сопровождение по статусам воронки

Кандидат проходит воронку лида; на каждом статусе у оператора своя
задача. Полная таблица статусов, кнопок и шаблонов сообщений — в
[LEADS.md](LEADS.md). Кратко:

- **анкета не заполнена** — бот собирает intake сам; вмешиваться не нужно.
- **ожидает решения** — карточка лида в чате лидов, оператор жмёт
  «Одобрить» / «Отклонить».
- **сбор документов / подача** — бот в режиме поддержки отвечает на
  вопросы; оператор ведёт визовую часть и жмёт «→ на визу» / «✅ подал».

## Типовые сбои

Большинство инцидентов — инфраструктурные. Полный разбор и команды — в
[DEPLOY.md → Troubleshooting](DEPLOY.md#troubleshooting). Чаще всего:

| Симптом | Куда смотреть |
|---------|---------------|
| Бот не отвечает никому | `/admin/status`, логи `docker compose logs -f app`, webhook (`/admin/ops` → Telegram) |
| Бот «молчит» на конкретный вопрос | Норма при `NO_CONTEXT` — ответьте через очередь `/admin/kb-suggestions` |
| Бот не отвечает в одном диалоге | Проверьте режим: возможно диалог завис в `human` или `queued` |
| Ответы стали хуже / медленнее | `/admin/analytics` (latency, no_context rate), `/admin/settings` (модель, RAG-флаги) |

## Куда смотреть

- **`/admin/status`** — активные флаги, размер базы знаний, состояние
  воронки. Первое место при «что-то не так».
- **`/admin/analytics`** — агрегаты RAG: разбивка путей, latency p50/p95,
  доля `no_context`.
- **`/admin/ops`** — операционные действия: переиндексация базы знаний,
  webhook, очередь userbot.
- **Логи** — `docker compose logs -f app`; на каждый ответ бот пишет
  провайдера, latency и число найденных фрагментов.
