# Анализ воркфлоу и выявленные пробелы (Gaps & Issues)

_Дата обновления: 2026-05-27_
_Статус: Аналитический отчет по вертикалям Recruitment и Exchange_

---

## 1. Рекрутинговые агентства (Китай / ОАЭ)
Вертикаль Phase 1. Основной фокус — найм артистов и персонала за рубеж.

### ⚠️ Проблемы и узкие места
1.  **Высокое трение на этапе Intake:** Анкета из 15 пунктов (включая видео танца и фото паспорта) требует от пользователя слишком много действий "здесь и сейчас". Отсутствие возможности поэтапного сбора ("дожима") ведет к потере лидов.
2.  **Жесткая привязка к типу вакансии:** Поле `dance_video_received` является обязательным в текущем шаблоне. Это блокирует использование шаблона для других вакансий (хостес, официанты, менеджеры) без перенастройки.
3.  **Отсутствие валидации документов (Vision Gap):** Система делает OCR паспорта, но не сопоставляет извлеченные данные (например, дату окончания) с требованиями визовой политики (минимум 6 месяцев до конца срока).
4.  **Сложность визового интервью:** 32 текстовых поля для заполнения анкеты на китайскую визу в чате — это высокий риск опечаток. Ошибки в именах родителей или адресах ведут к отказам.
5.  **Изоляция этапа `partner_review`:** Текущий воркфлоу не имеет интерфейса для внешних партнеров (работодателей в Китае), что вынуждает оператора вручную пересылать данные вне системы.

### 🚀 Предложения по улучшению
-   **CV Generator:** Автоматическая генерация PDF-профиля кандидата на основе собранных данных и фото.
-   **Smart Stop-loss:** Блокировка продвижения лида, если `passport_expiry` меньше критического срока.
-   **Интеграция с Консульствами:** Отображение актуальной доступности слотов на подачу документов (если доступно через API или парсинг).
-   **Multi-role Intake:** Динамическое изменение состава анкеты в зависимости от выбранной должности.

## 2. Обменные пункты (Пхукет)
Вертикаль Phase 1+. Фокус на обмене Крипто/RUB → THB.

### ⚠️ Проблемы и узкие места
1.  **Риск волатильности курса:** Между ручным подтверждением курса оператором и фактической оплатой клиентом проходит время. Отсутствие "Rate Lock" механизма создает риск убытков при резком движении рынка.
2.  **Ошибка в выборе сети (Network):** Текстовый ввод сети (TRC20/ERC20) недостаточно акцентирован. Ошибка пользователя ведет к безвозвратной потере средств.
3.  **Безопасность подтверждения оплаты:** Подтверждение получения средств (`payment_confirmed`) оператором вручную уязвимо для социальной инженерии и поддельных скриншотов чеков.
4.  **Риск выдачи QR:** Передача QR-кода на снятие наличных в открытом чате небезопасна. Отсутствует механизм подтверждения владения (OTP/контрольное слово).

### 🚀 Предложения по улучшению
-   **Crypto Rates API:** Интеграция с Binance/CoinGecko для получения курсов в реальном времени и автоматического расчета итоговой суммы.
-   **Blockchain Auto-Verification:** Интеграция с TronScan/Etherscan для автоматического подтверждения транзакции по хэшу (TXID).
-   **AML Integration:** Проверка кошельков отправителей через сервисы скоринга (AMLBot и аналоги).
-   **QR-Pool Management:** Пакетная загрузка QR-кодов в админку с автоматической выдачей первого свободного.

## 3. Общие системные пробелы (Admin & Core)

### ⚠️ Выявленные дефициты
1.  **Система уведомлений оператора:** Оператор узнает о действиях лида только находясь в Admin UI. Отсутствует "Operator Bot" для алертов в Telegram/WhatsApp.
2.  **Отсутствие исходящих Webhooks:** Невозможно интегрировать систему с внешними CRM (amoCRM, Bitrix24) или бухгалтерским ПО для фиксации сделок.
3.  **Ограниченность типов данных:** В `stage_fields` не хватает специализированных полей с валидацией (например, поле "IBAN", "Крипто-кошелек" с проверкой чек-суммы).
4.  **Аудит финансовых транзакций:** В `audit_log` фиксируются общие события, но нет детализации по критическим объектам (какой именно QR был выдан, какой хэш транзакции был привязан).

### 🚀 Стратегические направления
-   **Operator Companion Bot:** Отдельный бот для сотрудников агентства для оперативного реагирования.
-   **External Integration Layer:** Шина для отправки данных в сторонние сервисы по завершении этапов.
-   **Batch Processing:** Инструменты массовой обработки лидов или документов.
