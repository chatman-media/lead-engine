# Использование ИИ и требования к серверу

Где бот зовёт LLM, сколько это стоит и какое железо нужно. Про выбор
провайдера и `.env`-настройки — [DEPLOY.md](DEPLOY.md#choosing-an-llm-provider)
и [README](../README.md#выбор-llm-провайдера).

## Где используется ИИ

Бот делит ИИ на три независимых канала:

| Канал | Зачем | Провайдер | Частота |
|-------|-------|-----------|---------|
| **Chat** | RAG-ответы кандидату, персона | OpenAI / OpenRouter / Ollama | каждое сообщение кандидата |
| **Embeddings** | Векторный поиск по базе знаний | OpenAI / Ollama | каждый запрос + при индексации KB |
| **Vision** | Классификация фото (паспорт / в полный рост / …) | OpenRouter | каждое фото кандидата (если `VISION_ENABLED`) |

Chat и embeddings настраиваются **раздельно**: у OpenRouter нет
endpoint'а для embeddings, поэтому при `LLM_PROVIDER=openrouter` эмбеддер
всё равно отдельный (OpenAI или локальная Ollama).

### Дополнительные LLM-вызовы

Помимо основного ответа, некоторые функции добавляют свои вызовы — это
прямо влияет на стоимость:

- **RAG-надстройки** (`docs/RAG_LAYERS.md`, все opt-in): query rewrite и
  reflection добавляют по LLM-вызову на ход; skill grading, memory
  extraction, conversation summary — фоновые вызовы после ответа.
- **Self-play / coaching** — тренировочный цикл: матчи, судья, coach.
  Запускается вручную или по расписанию, не на трафике кандидатов.

Базовый минимум — 1 chat-вызов + 1 embeddings-вызов на сообщение. Каждый
включённый слой — это +1 вызов; включайте по одному (см.
[ROADMAP → recommended turn-on order](ROADMAP.md)).

## Ориентир по стоимости

Точные цены зависят от провайдера и модели. Относительная стоимость
рекомендуемых chat-моделей:

| Модель | Цена | Комментарий |
|--------|------|-------------|
| `anthropic/claude-haiku-4.5` | `$$` | дёшево, быстро, отличный русский — дефолт |
| `anthropic/claude-sonnet-4.6` | `$$$$` | премиум, лучший few-shot |
| `openai/gpt-4o-mini` | `$` | быстро и дёшево |
| `google/gemini-2.5-flash` | `$` | самый дешёвый из frontier-class |
| `qwen/qwen3-8b` | `$` | то же, что локальный Qwen3, но в облаке |
| локальная Ollama | `$0` за токены | платите только за железо/электричество |

Что увеличивает счёт:
- объём диалогов (chat-вызовы линейны по числу сообщений);
- включённые RAG-слои (каждый — дополнительный вызов на ход);
- `VISION_ENABLED` (вызов на каждое фото);
- self-play / coaching (отдельный поток вызовов).

Как удешевить: дешёвая chat-модель + embeddings на локальной Ollama
(эмбеддеры — 100–500M параметров, тянет даже скромный CPU), либо
полностью локальный стек на Ollama (нулевая пер-токенная цена ценой
требований к железу). Модель и RAG-флаги переключаются на лету в
`/admin/settings` без редеплоя.

## Требования к серверу

Проверенные базовые показатели (см. [DEPLOY.md → Resource sizing](DEPLOY.md#resource-sizing)):

| Конфигурация | RAM | CPU / GPU | Latency на ход |
|--------------|-----|-----------|----------------|
| **Бот + внешний LLM** (OpenAI / OpenRouter) | ~150 МБ idle, ~250 МБ под нагрузкой | 1 ядра достаточно | сетевая задержка провайдера |
| **+ Ollama (CPU)** | +6–12 ГБ (qwen3:8b q4_K_M ≈ 5 ГБ, bge-m3 ≈ 1 ГБ) | многоядерный CPU | 10–60 с |
| **+ Ollama (GPU)** | +12 ГБ VRAM | 12 ГБ consumer GPU (3060 / 4060 Ti) | < 1 с |

Рекомендации:
- **API-провайдер** (OpenAI / OpenRouter) — самый дешёвый вход по железу:
  обычного VPS (1 CPU, 512 МБ–1 ГБ RAM) хватает, вся тяжёлая часть на
  стороне провайдера.
- **Локальный Ollama на CPU** — для низкого трафика; при росте нагрузки
  берите модель меньше (`qwen3:4b`, `llama3.2:3b`), иначе latency
  становится некомфортной.
- **Локальный Ollama на GPU** — sub-second ответы; в `docker-compose.yml`
  раскомментируйте блок `deploy.resources` для проброса NVIDIA GPU.

### База данных

PostgreSQL **16+** с расширением **pgvector** (векторный поиск базы
знаний). Бот на старте делает `CREATE EXTENSION vector` — бинарники
pgvector должны быть установлены на хосте Postgres, иначе бот падает при
первой загрузке. Варианты провижна (Docker-образ `pgvector/pgvector`,
пакет `postgresql-NN-pgvector`, Supabase) — [DEPLOY.md → Database](DEPLOY.md#database).

Сам бот без локального тома: всё состояние в PostgreSQL, перезапуск
контейнера данные не теряет. Бэкапы — [DEPLOY.md → Persistent data](DEPLOY.md#persistent-data).
