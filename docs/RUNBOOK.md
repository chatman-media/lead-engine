# Руководство владельца

Пошаговая инструкция, как содержать бота без программиста: оплата ИИ,
смена ключей, перезапуск, восстановление базы. Технические детали
деплоя — в [DEPLOY.md](DEPLOY.md); сопровождение диалогов — в
[SUPPORT.md](SUPPORT.md).

Почти всё делается в админке: откройте в браузере `https://ваш-домен/admin`
и войдите под своим логином оператора.

---

## Оплата OpenRouter

Бот отвечает кандидатам через OpenRouter — это платный сервис, деньги
списываются за каждый ответ.

**Как пополнить:**
1. Зайдите на <https://openrouter.ai> под аккаунтом, где заведён бот.
2. Откройте раздел **Credits** (<https://openrouter.ai/credits>).
3. Нажмите **Add Credits**, привяжите карту, внесите сумму.
4. Деньги зачисляются сразу — перезапуск бота не нужен.

**Совет:** в настройках OpenRouter можно включить **Auto Top-Up**
(автопополнение) — баланс будет пополняться сам, и бот не остановится.

## Баланс: как не остаться без денег

Бот сам следит за балансом OpenRouter:

- **Карточка в админке.** `/admin/status` → карточка **«Баланс
  OpenRouter»**: остаток, сколько потрачено. Красная — баланс
  заканчивается.
- **Уведомление в Telegram.** Когда остаток падает ниже порога, бот
  присылает личное сообщение оператору (тому, чей Telegram ID указан в
  настройках). Порог по умолчанию — $5, меняется переменной
  `OPENROUTER_LOW_BALANCE_USD`.
- **Проверить вручную.** `/admin/ops` → «Баланс OpenRouter» → «Проверить
  баланс».

Чтобы уведомления приходили — в `/admin/settings` → «Параметры бота»
должен быть заполнен **«Telegram ID оператора»** (узнать свой ID:
напишите боту [@userinfobot](https://t.me/userinfobot)).

## Смена ключей и токенов

Все ключи редактируются в админке — файлы трогать не нужно.

1. Откройте `/admin/settings` → секция **«Ключи и токены»**.
2. Найдите нужный ключ (OpenRouter, OpenAI, токен Telegram-бота и т.д.).
   Поле показывает только хвост текущего значения — это нормально.
3. Вставьте новый ключ в поле. Пустое поле = оставить прежний ключ.
4. Для ключей OpenRouter / OpenAI / токена бота есть кнопка
   **«Проверить»** — нажмите, чтобы убедиться, что ключ рабочий, ещё до
   сохранения.
5. Нажмите **«Сохранить»**, затем **«Применить и перезапустить»**.
6. Через ~15 секунд обновите страницу — бот работает с новым ключом.

> После смены **секрета вебхука Telegram** заново привяжите вебхук:
> `/admin/ops` → «Для разработчика» → панель Telegram.

## Перезапуск бота

Перезапуск нужен после смены ключей или параметров.

- **Из админки:** `/admin/ops` → «Перезапустить бота» → «Перезапустить».
  Либо кнопка «Применить и перезапустить» на странице настроек.
- **С сервера:** `sudo systemctl restart chatman`.

Кнопка перезапуска работает, только если сервис настроен на
авто-восстановление. Проверьте на сервере:

```bash
systemctl cat chatman | grep Restart
```

Должно быть `Restart=always`. Если строки нет — возьмите готовый юнит из
репозитория `deploy/chatman.service`, скопируйте в
`/etc/systemd/system/chatman.service`, затем:

```bash
sudo systemctl daemon-reload
sudo systemctl restart chatman
```

Без `Restart=always` кнопка просто остановит бота, и поднимать его
придётся вручную.

## Обновление кода

Когда вышли новые правки — на сервере:

```bash
bash /home/chatman/app/deploy.sh
```

Скрипт сам забирает код, ставит зависимости, пересобирает админку и
перезапускает сервис. Данные в базе при этом не теряются.

## База данных: пересоздание и восстановление

Вся переписка, лиды и настройки лежат в PostgreSQL. Бот без локальных
файлов — перезапуск/переустановка кода базу не трогают.

**Если базу пришлось пересоздать с нуля**, при первом запуске бот
**сам** восстанавливает: схему таблиц, расширение pgvector, встроенные
стили продаж, каталог навыков, стандартные вакансии.

**Вручную** нужно вернуть три вещи:
1. **Аккаунт оператора** — на сервере:
   `bun scripts/create-admin.ts ваш@email пароль`
2. **Вебхук Telegram** — `/admin/ops` → панель Telegram → «Set».
3. **База знаний** — `/admin/ops` → «Обновить базу знаний бота».

**НЕ восстанавливается без резервной копии:** история переписок, лиды,
заметки операторов, решения по вопросам. Поэтому делайте бэкапы.

**Резервная копия** (на сервере):

```bash
bash /home/chatman/app/scripts/backup.sh   # пишет в ./backups/
```

Восстановление из копии и расписание бэкапов — см.
[DEPLOY.md → Persistent data](DEPLOY.md#persistent-data).

## Чеклист «бот молчит»

Если бот перестал отвечать кандидатам — проверьте по порядку:

1. **`/admin/status` → «Bot health».** Красное «unreachable» — проблема
   с токеном Telegram-бота или сам Telegram недоступен.
2. **«Баланс OpenRouter».** $0 — пополните счёт (см. выше).
3. **Режим диалога.** Возможно конкретный диалог завис в ручном режиме —
   см. [SUPPORT.md](SUPPORT.md) про режимы и «Release».
4. **Сервис запущен:** на сервере `systemctl status chatman`. Не
   активен — `sudo systemctl restart chatman`.
5. **Вебхук:** `/admin/ops` → панель Telegram → «Info». Растёт
   `pending_update_count` — бот не успевает отвечать; смотрите логи
   (`journalctl -u chatman -f`).

Подробный разбор сбоев — [DEPLOY.md → Troubleshooting](DEPLOY.md#troubleshooting).
