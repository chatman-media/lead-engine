# Scrum-команда агентов над доской Lead Engine

Мульти-агентный «скрам-движок» поверх GitHub Projects v2 доски **Lead Engine** (`chatman-media`, проект №5). По команде берёт карточки из колонки **Todo** и проводит каждую через конвейер ролей, открывая Pull Request и двигая карточку по доске.

## Поток

```
Todo ──▶ In Progress ──▶ [ дизайн → план → код+PR → (ревью ∥ QA) ] ──▶ In Review ──▶ (человек мёржит) ──▶ Done
                                                                   └─ при провале ──▶ обратно в Todo (с причиной)
```

**Гейт перехода в In Review:** `impl.success && review=approve && qa ∈ {pass, blocked_infra}`. У QA три исхода:
- `pass` — стенд зелёный, критерии выполнены;
- `fail` — сломано **по вине PR** → карточка обратно в Todo с блокерами;
- `blocked_infra` — критерии выполнены и PR-проверки зелёные, но обязательная команда стенда красная по **пред-существующей** причине (доказано на base) → карточка всё равно в In Review, инфра-поломка отмечается отдельно. Это разводит «PR сломан» и «стенд сломан», чтобы хорошую работу не бросало в Todo из-за чужой инфра-поломки.

## Роли (`.claude/agents/`)

| Роль | Файл | Что делает | Пишет код? |
|---|---|---|---|
| 🎨 Продуктовый дизайнер | `product-designer.md` | задача → спека + критерии приёмки + UX | нет |
| 🧭 Техлид/архитектор | `tech-lead.md` | спека → исполнимый план + затрагиваемые файлы | нет |
| 🛠 Инженер-исполнитель | `implementer.md` | код в изолированном worktree, typecheck+biome, PR | **да** |
| 🔎 Ревьюер | `reviewer.md` | ревью дифа PR: корректность, безопасность, конвенции | нет |
| ✅ QA | `qa.md` | выкатывает ветку PR, гоняет тестовый стенд, сверяет критерии | нет |
| 🗂 Грумер (triage) | `triage.md` | оценивает Backlog: готовность, размер, приоритет | нет |

Оркестратор (скрам-мастер) — это не агент, а команда `/sprint`: она читает доску, двигает карточки и запускает конвейер через инструмент **Workflow**.

## Команды

- **`/sprint [N]`** — взять N карточек Todo (по умолчанию 3) и прогнать спринт. Карточки уходят в In Progress, по итогу — в In Review (с PR) или обратно в Todo (с причиной). PR **не мёржится автоматически**.
- **`/groom [N]`** — оценить N карточек Backlog силами triage-агентов и (после подтверждения) поднять готовые в Todo.

## Файлы

```
.claude/
├── agents/                 # 6 ролей-субагентов
├── commands/
│   ├── sprint.md           # оркестратор спринта
│   └── groom.md            # груминг бэклога
└── scrum/
    ├── board.config.json   # ID проекта/полей/опций + qa.commands + autoMerge
    ├── board.mjs           # CLI-обёртка над gh (list/move/comment/issue/status)
    ├── sprint.workflow.js  # Workflow-конвейер (pipeline по карточкам)
    └── README.md
```

## Хелпер доски (вручную, для отладки)

```bash
bun .claude/scrum/board.mjs status                  # счётчики по колонкам
bun .claude/scrum/board.mjs list "Todo"             # карточки колонки (JSON)
bun .claude/scrum/board.mjs issue 123               # issue целиком (JSON)
bun .claude/scrum/board.mjs move <itemId> "In Review"
echo "текст" | bun .claude/scrum/board.mjs comment 123
```

## Безопасность и границы

- **Авто-мёрж выключен** (`autoMerge:false`). Конвейер доводит до открытого PR и переводит карточку в In Review; мёрж и переход в Done — за человеком. Мёрж необратим — даже при `autoMerge:true` оркестратор сперва спросит подтверждение.
- Конвейер **создаёт PR и пишет комментарии** в issue/PR — это его задача и явно запрошенное поведение. Один сводный комментарий на карточку.
- Изоляция: `implementer` и `qa` работают в отдельных git worktree (параллельные правки не конфликтуют).
- Карточки-«агенты» не назначаются на реальных GitHub-пользователей (их нет) — роль и статус видны по колонке Status и сводному комментарию.

## Настройка под себя

- **Тестовый стенд / сценарии по PR** → правь `qa.commands` в `board.config.json` (например добавь `bun run quality:tool-regressions` или прогон сидов/смоук под вертикаль). QA-агент читает этот список.
- **Сколько карточек за спринт** → `sprint.defaultCardLimit` / `sprint.maxParallel`.
- **Сменились колонки на доске** → обнови `status.*` (ID опций: `gh project field-list 5 --owner chatman-media`).
- Хочешь автономный режим (по расписанию вместо команды) — это надстройка через `/schedule` или cron поверх `/sprint`; сейчас намеренно только по команде.
